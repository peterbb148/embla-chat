# Validation records

These records distinguish production simulator UI, real-model host tests, physical iPhone
observations and actual iCloud-provider checks. Passing a fixture or build does not prove
model inference or cloud transfer.

- [iPhone experience delivery acceptance](epic4-validation.md)
- [Original working single-chat checkpoint](working-version-validation.md)
- [Physical iPhone measurements and installation](device-validation.md)
- [Chat UI observations](chat-ui-validation.md)
- [Context compaction](context-compaction.md) and [context usage](context-usage.md)
- [Persistence and iCloud](chat-persistence.md)
- [History](chat-history.md), [Projects](projects.md) and [quick actions](quick-actions.md)
- [Skills and MCP host/transport evidence](skills-and-tools.md)
- [Repository security and merge gates](repository-security.md)

Each feature record identifies its evidence and limits. The delivery acceptance record
maps the assembled app to those checkpoints; it does not turn older device observations
into a claim about an untested newer build.
