# Chat history (#33)

The leading menu opens a left sidebar with the current and previous chats, New Chat,
and Settings. Chat titles use the first user-message line (or a local draft for an unsent
chat). Titles are not generated by another service. No search, deletion, project grouping
or per-chat cloud switch is introduced by this issue.

New Chat saves the current conversation instead of deleting it. Selecting a previous chat
restores its IDs, exact transcript, rolling summary and separate draft. Navigation cancels
and drains active generation before resetting runtime context. Partial output is marked
interrupted; reopening never resumes generation automatically. The composer stays locked
until the replacement archive is durable. Failed navigation saves preserve the visible
chat and expose the storage error. The last two completed exchanges and compaction policy
continue to apply independently to each selected chat.

## Local document and migration

The atomic local `active-chat.json` archive now includes an optional `history` array of
`SavedConversation` entries alongside the selected snapshot and draft. Missing history is
the supported single-chat migration format; existing content is retained. Duplicate chat
IDs, invalid summary boundaries and corrupt documents fail clearly. All recovered streaming
responses, including inactive ones, become interrupted. The local archive remains excluded
from automatic iCloud backup. Draft checkpoint intervals retain the same abrupt-exit limit
as the original persistence implementation.

## One global iCloud switch

Off remains the default. Creating, browsing and switching chats while Off never opens the
provider. Explicit consent for On covers **all saved conversations and summaries**, including
future chats. Drafts, device selection, folder bookmarks and model weights stay local. Per-chat
cloud controls are deferred to #42.

The existing `EmblaChat/Chats/ActiveChat.json` path now holds a format-2 `ConversationLibrary`
with a `chats` array, sorted by stable ID. Keeping the same path avoids two competing cloud
sources. The prior format-1 single-chat document is explicitly decoded as a one-chat library;
corrupt format-2 data is never retried as an older format. An older saved synchronization
fingerprint can require an explicit library choice on first synchronization after upgrade.
Older app builds cannot read the upgraded format; use the updated app on devices sharing it.

Conflict choices apply to the **whole library**, rather than silently merging transcripts.
Consent warns that choosing the cloud copy replaces all local chats and drafts. A draft in
any inactive chat prevents automatic download, just like a draft in the selected chat.
Selection stays on the current ID if that ID exists in an accepted library; otherwise the
first stable-ID entry becomes selected. Selecting a chat alone does not change the cloud
library. Settings reports chat/message counts for each choice. Existing coordinated writes,
content fingerprints, unresolved-version checks, cancellation and saved-preference barriers
remain in effect. Skills contents remain untouched.

## Validation boundary

Package tests exercise actual temporary local/coordinated files and explicitly injected
cloud/inference fixtures. They cover migration, all-chat opt-in without drafts, inactive-draft
conflicts, exact summary/draft restoration after restart, interrupted navigation and failed
writes. Simulator UI checks use the production app without model downloads or synthetic
assistant responses. They do not prove real iCloud transfer or model inference. Physical
single-chat iCloud evidence in chat-persistence.md predates this format; the user deferred real multi-chat provider
validation to unplanned #45. It is not an Epic 4 completion gate.

Local Xcode 27.2 validation: 112 package cases and all seven production UI checks passed on
the existing iPhone 17 Pro/iOS 27.2 simulator. The history UI check restores both drafts after
process restart. No extra local simulator is created for subsequent validation.

Real-host inference on Apple M1/macOS 26.7.3 with the verified pinned model passed the
opt-in `realHostHistoryRestoresTwoIndependentConversationContexts` test in 40.23 seconds.
Actual model-generated chats retained BLUE PENGUIN and RED FOX independently. Switching
back to the first chat recalled BLUE PENGUIN; a fresh controller/session after restart
reopened the second and recalled RED FOX. Neither reply included the other chat's fact.
This is functional host evidence, not simulator inference or iPhone performance evidence.

The production simulator's sidebar and restored first-chat draft were also inspected visually.
The personal-iCloud attempt was cancelled because Files reported Drive off and the user chose
"Defer the real iCloud check". Settings remained Off. The existing Mac cloud document's hash
was unchanged and the empty preparation folders were removed. No real transfer is claimed.
